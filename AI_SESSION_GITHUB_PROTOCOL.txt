📌 القاعدة الذهبية: خطوة واحدة، تنفيذ، تسليم، وقفة، انتظار موافقة
-------------------------------------------------------------------
أي مهمة من أي ملف Checklist في هذا الريبو (WORKSHOP_TASKS_CHECKLIST.txt
أو WPFUI_INTEGRATION_CHECKLIST.txt أو أي ملف تاني هيتضاف بنفس النمط)
لازم تتنفذ بالترتيب ده بالظبط، من غير قفز خطوات ولا تجميع أكتر من
خطوة في نفس الرد، حتى لو المستخدم قال "كمل" أو "خلص بسرعة":

1. اقرا الملف ده كامل أولًا (لو أول مرة تفتحي الريبو).
2. اقرا قسم "آخر توقف" في ملف الـChecklist المطلوب اشتغالي عليه
   (اسألي المستخدم أي ملف لو مش واضح من الطلب).
3. نفّذي **مهمة واحدة بس** — أول عنصر لسه [ ] في القائمة.
4. اعملي commit + push فعلي على GitHub (طريقة الربط تحت).
5. حدّثي نفس ملف الـChecklist: علّمي [x] + سطرين في "سجل التنفيذ"
   + حدّثي "آخر توقف" للمهمة الجديدة.
6. اعملي commit + push تاني لتحديث ملف الـChecklist نفسه (أو ضمّيه
   في نفس commit الخطوة 4 — الاتنين مقبولين، المهم يوصل GitHub).
7. سلّمي للمستخدم **ملف .zip كامل** للمشروع بعد التعديل (زي ما هو
   على GitHub بالظبط دلوقتي).
8. بعد التسليم مباشرة: اعرضي بالتفصيل **إيه اللي هتعمليه في الخطوة
   الجاية** (اسم المهمة + الملفات المتوقع تتعدل + أي مخاطرة محتملة)،
   ثم **قفي تمامًا واستني موافقة صريحة** من المستخدم قبل أي تنفيذ.
9. ما تنفذيش الخطوة الجاية إلا بعد رد صريح بالموافقة (زي "تمام
   كمّلي" أو "أيوه"). رفض أو صمت المستخدم = وقف.

الاستثناء الوحيد: لو ملف الـChecklist نفسه فيه تعليمة مختلفة صراحة
(زي WORKSHOP_TASKS_CHECKLIST.txt اللي بيسمح بتنفيذ تلقائي بدون
انتظار موافقة لكل خطوة) — في الحالة دي اتبعي تعليمات الملف نفسه،
لكن قاعدة "خطوة واحدة بس + تسليم zip + توثيق" تفضل ثابتة دايمًا.

-------------------------------------------------------------------
🔗 طريقة الربط الفعلي بـ GitHub (تجربة موثّقة، فيها دروس مستفادة)
-------------------------------------------------------------------
مفيش أي أداة/Connector جاهز متاح حاليًا يدّي وصول مباشر لـGitHub.
الطريقة اللي بتشتغل فعليًا: استخدام git من بيئة تنفيذ الكود مباشرة،
لأن github.com وapi.github.com متاحين في شبكة بيئة التنفيذ.

الخطوات:

1. اطلبي من المستخدم يعمل GitHub Personal Access Token (Fine-grained)
   بالمواصفات دي بالظبط:
   - Repository access: "Only select repositories" → يحدد الريبو ده
     بس (مش "All repositories").
   - Permissions → Repository permissions → "Contents" = Read and write
     (ده المطلوب فعليًا للـpush؛ "Metadata" بيتحدد Read-only تلقائي
     وده كافي، محتاجيش صلاحيات تانية زي Security advisories).
   - مدة صلاحية قصيرة (يوم/أسبوع) — نصيحة أمان، مش شرط تقني.

2. ⚠️ الدرس الأهم المستفاد: **لازم التوكن يتعمل من نفس حساب GitHub
   اللي هو فعليًا Admin/Owner على الريبو** — مش أي حساب تاني حتى لو
   المستخدم قال إنه "الأدمن". قبل ما تطلبي التوكن، تأكدي إزاي:
   - لو عندك شك، اطلبي من المستخدم يفتح
     https://github.com/{owner}/{repo}/settings ويقول لك هو شايف
     إيه في القائمة الجانبية. لو شايف بس "Secrets and variables"
     ورسالة "You don't have access to repository options" — يبقى
     الحساب ده **مش** الأونر الحقيقي، وأي توكن هيتعمل منه هيفشل في
     الـpush برسالة 403 "Permission ... denied to {username}".
   - لو شايف تبويبات كاملة (General, Collaborators, Branches,
     Danger Zone فيه Delete/Transfer repository) — يبقى فعلاً Admin
     كامل، وتقدري تكملي بأمان.
   - لو حصل الخطأ ده فعلاً (توكن من حساب غلط)، أسهل حل مش إضافة
     الحساب كـ Collaborator (بياخد وقت + محتاج قبول دعوة) — الأسهل
     إنك تطلبي توكن **جديد من الحساب الصح مباشرة** بنفس المواصفات
     فوق.

3. لما يوصلك التوكن (شكله github_pat_...)، استخدميه فورًا كده:

   mkdir -p /home/claude/repo_work && cd /home/claude/repo_work
   export GH_TOKEN="التوكن_هنا"
   git clone "https://x-access-token:${GH_TOKEN}@github.com/OWNER/REPO.git" repo
   cd repo
   git config user.email "claude@anthropic.com"
   git config user.name "Claude (via user request)"
   # ... تعديل الملفات المطلوبة فعليًا هنا ...
   git add <الملفات المتعدلة>
   git commit -m "رسالة وصفية بالمهمة اللي اتنفذت"
   git push origin master

4. **قاعدة أمان إلزامية**: أي وقت بتطبعي output من أمر git فيه رابط
   الـremote (زي أخطاء الـclone/push)، فلتري التوكن من الـoutput قبل
   ما يظهر للمستخدم، مثلًا:
   `... 2>&1 | sed 's/github_pat_[A-Za-z0-9_]*/[REDACTED]/g'`
   وبعد أي push ناجح، شيلي التوكن من remote URL المحفوظ محليًا:
   `git remote set-url origin "https://github.com/OWNER/REPO.git"`
   (مش لازم تشرحي للمستخدم كل التفاصيل التقنية دي، بس نفذيها).

5. التوكن بتاع المستخدم مؤقت وبيُستخدم في الجلسة دي بس — ملوش أي
   تخزين دائم عندك. لو المحادثة خلصت واحتجتي تكملي في جلسة جديدة،
   لازم تطلبي توكن جديد (نفس الخطوات فوق) — القديم ممكن يكون
   انتهت صلاحيته أو اتلغى من المستخدم.

6. لو الـpush فشل برسالة تانية غير 403 (زي auth error عام أو
   الريبو مش موجود)، متحاوليش تخمّني الحل — اعرضي الخطأ للمستخدم
   بوضوح واسأليه يتأكد من اسم الريبو/الفرع/صلاحية التوكن.
